## 4. Startup & VC Ecosystem — Talent Networks, Accelerators, Portfolio Boards

Startups under ~200 people almost never syndicate to Indeed/LinkedIn and rarely run a university recruiting funnel, so a CS+AppliedMath undergrad is invisible to them unless you go to where they actually post: the VC portfolio board their investor pays for, the accelerator's alumni board, or a monthly text thread on Hacker News. The decisive discovery in this domain is that **the VC boards are not ~60 separate scrapes — they are two shared platforms (Getro and Consider) plus a small tail**, and both expose unauthenticated JSON. One Getro client + one Consider client + a table of ~55 network IDs / board slugs yields well over 150,000 raw postings, of which the intern/new-grad slice is the target. A second, compounding payoff: every Getro/Consider job object carries a direct `url`/`applyUrl` pointing at the company's real ATS (Greenhouse/Lever/Ashby/Workable), which makes this family the single best **ATS-token discovery engine** in the whole pipeline — it feeds the ATS section for free. Yield is high and effort is low *after* the two clients exist; before that, it looks deceptively like 60 bespoke scrapers, which is the trap most people fall into.

All endpoints, network IDs, board slugs and job totals below were probed live (2026-08-01) unless a row says `conf:low`.

**Ingestion notes**

*Build order.* One Getro client + one Consider client covers ~55 of the ~70 VC/accelerator boards in this section. Everything else in 4.7 is a one-off or a documented dead end. Do not write per-firm scrapers.

*Getro — hardcode these.* Discovery: `GET https://<host>/jobs` → parse `<script id="__NEXT_DATA__" type="application/json">` → `props.pageProps.network.id|slug|name` and `props.pageProps.initialState.jobs.total`. Bulk pull: `POST https://api.getro.com/api/v2/collections/<network_id>/search/jobs`, headers `Content-Type: application/json`, body `{"hitsPerPage":100,"page":<n>,"filters":{}}` → `results.jobs[]`. No auth, no cookie, no CSRF. **Rate limiting is real and abrupt**: after roughly a dozen rapid calls the API flips to `HTTP 406` for everything from that IP, including previously-working bodies — treat 406 as "backoff", not "bad request", sleep ≥60s, and cap at ~1–2 rps with jitter. The SSR `__NEXT_DATA__` path (20 jobs/page, `?page=N`) keeps working when the API is 406-ing, so implement it as the fallback. Canonical host is always `https://<network-slug>.getro.com/jobs`; vanity CNAMEs (`jobs.<firm>.com`) rot, the `.getro.com` host does not. A wrong slug returns a Next.js `/not-found` page — that is your liveness test. Note `/api/v2/collections/...` (free, public) vs `/v2/networks/...` (401, customer-only) — the path shape is the difference.

*Consider — hardcode these.* Discovery: `GET https://<host>/jobs` → regex `window.serverInitialData = ({.*?});` → `.board.id`. Bulk pull: `POST https://<host>/api-boards/search-jobs`, headers `Content-Type: application/json` + `Accept: application/json`, body `{"meta":{"size":100},"board":{"id":"<slug>","isParent":true},"query":{},"grouped":false}`. Response: `{jobs:[…], total:<int>, availableFilters:{…}, meta:{size, sequence}}`. **Pagination is cursor-based** — pass the previous response's `meta.sequence` back in `meta.sequence` for the next page; there is no page number. An empty/omitted `board` yields `500 BOARDS_JOBS_ERROR "Cannot wrap undefined with r.expr()"` — that error is your signal the board object is malformed, not that the endpoint is down. The `csrfToken` in `serverInitialData` is **not** required for search. Filter server-side with `query.jobTypes` / `query.jobSeniorities` rather than pulling 9,593 Sequoia rows and filtering locally.

*The ATS dividend.* Every Getro job has `url` and every Consider job has `applyUrl` pointing at the company's real ATS — overwhelmingly `boards.greenhouse.io/<token>`, `jobs.lever.co/<org>`, `jobs.ashbyhq.com/<org>`, `apply.workable.com/<org>`. Regex those out and you get a continuously-refreshed, deduped registry of ~10k+ startup ATS tokens for free. Feed it to the ATS-native section; it is worth more than the postings themselves because ATS endpoints are stable, unlimited, and unbanned. Consider additionally exposes `companyDomain` and `companyStaffCount`, which lets you filter to <200-person companies before you spend a request.

*YC.* `workatastartup.com` is Rails + Inertia: either scrape the `data-page` attribute (HTML-entity-decode, then JSON-parse) or re-request with `X-Inertia: true` + `X-Inertia-Version: <version>` for clean JSON. The version string rotates on deploy; read it from `data-page` each run or you get a 409 version-mismatch. **DataDome guards the host** — it returned 406 to a normal client after a handful of requests. Budget for a residential proxy or a slow polite crawl; datacenter IPs get blocked fastest. `ycombinator.com/jobs` uses the same Inertia mechanism with weaker protection and is the safer default for volume. For company metadata prefer `yc-oss.github.io/api` (static, unlimited, verified fresh 2026-08-01) over the Algolia index, whose public key YC rotates.

*HN.* Never scrape `news.ycombinator.com` HTML. `hacker-news.firebaseio.com/v0/user/whoishiring.json` → `submitted[]` → `item/<id>.json` to identify the current month's thread, then `hn.algolia.com/api/v1/search_by_date?tags=comment,story_<id>&hitsPerPage=1000` for the payload. 10,000 req/hr, no key, no anti-bot. Only top-level comments (`parent_id == story_id`) are job posts; replies are chatter. Companies self-format as `Company | Role | Location | REMOTE | Salary | contact` — the pipe-delimited convention holds for maybe 70% of posts; keyword-match `intern`, `internship`, `co-op`, `part-time`, `new grad` on the raw text for the rest. Use `hnhiring.com/<month>-<year>` as a parsed cross-check.

*Seasonal calendar.* HN threads post at ~11:00 ET on the **first weekday of each month** and accumulate comments for ~72 hours — poll on days 1–4. YC now runs four batches a year; portfolio hiring spikes in the **6–10 weeks after each Demo Day**, and `workatastartup.com` volume roughly doubles then. VC fellowship deadlines are the earliest and easiest to miss: **KP Fellows and most summer fellowship programs open Sept–Oct and close Nov–Jan for the *following* summer** — a full two quarters ahead of big-tech intern timelines. Neo Scholars runs late fall → winter. Getro and Consider boards refresh **daily** (Getro explicitly re-crawls portfolio careers pages each day and drops closed roles), so a daily pull is right; hourly is waste and will get you 406'd. SEC Form D filings arrive continuously with a 15-day-post-sale deadline, so the hiring signal leads the posting by roughly 2–8 weeks. Startup hiring dips hard mid-December through early January and again in late August.

*Politeness that actually matters.* SEC EDGAR **requires** a `User-Agent` containing a real name and email or it 403s — this is the one source that will hard-block you for a missing header rather than for volume. Getro flips to 406, Wellfound/TrueUp/startup.jobs/Product Hunt-web/Crunchbase all 403 plain curl (Cloudflare + DataDome), and workatastartup 406s. Everything in 4.5/4.6 answered a bare `curl` with a normal desktop UA — that is the whole point of prioritizing them.

**Traps & dead ends**

- **Guessing `jobs.<firm>.com` is a coin flip.** Of ~60 subdomains probed, roughly half did not resolve at all, and several that *did* resolve returned a Getro `/not-found` page — a decommissioned board that still answers HTTP 200 at the host level. Always verify against `network.id` or `board.id`, never against a 200.
- **`<slug>.getro.com` collisions are the nastiest trap in this section.** `atomic.getro.com` is "Atomic FI" (a portfolio company, 0 jobs) — **not** Atomic the venture studio. `neo.getro.com` is "Neo.Tax" — **not** Neo the student accelerator. `village.getro.com` is a generic "Village" network with 0 jobs — **not** Village Global. `matrix.getro.com` is a 0-job "Matrix" network of unclear provenance. Slug-guessing on `.getro.com` silently produces plausible-looking garbage. Always check `network.name` and `jobs.total` before trusting a slug.
- **Duplicate networks across vanity domains.** `jobs.ggvc.com` and `jobs.notablecap.com` are both network `764` (GGV rebranded to Notable Capital). `jobs.bcv.com` and `jobs.baincapitalventures.com` are both Consider board `bain-ventures`. Dedupe on `network_id` / `board.id`, not on hostname, or you will double-count thousands of rows.
- **Decommissioned Getro boards that still serve a page**: `jobs.coatue.com`, `jobs.boldstart.vc`, `jobs.susaventures.com`, `jobs.amplifypartners.com`, `jobs.joinef.com`. All return the Getro not-found shell. Marked T0 above so they are not re-investigated.
- **Late-stage/crossover funds do not run talent boards.** Tiger Global, Coatue, Dragoneer, ICONIQ, Altimeter — every candidate host was dead. Do not spend time here; the yield is structurally zero because these funds don't do talent services.
- **Benchmark deliberately has no board.** Not an oversight, a policy. Same practical outcome for Sutter Hill (in-house incubation, no public talent surface).
- **`jobs.gem.com` is dead (404).** "Jobs by VC" as a Gem-hosted product no longer resolves. Some Getro/VC pages still contain the string; it's residue.
- **Otta is gone** — folded into Welcome to the Jungle at `app.welcometothejungle.com`. **AngelList Talent is gone** — it is Wellfound, and `angel.co/jobs` is legacy. Both are still cited constantly in "best startup job boards" listicles, which is how they end up in catalogs like this one.
- **On Deck is not what the 2021 write-ups describe.** `beondeck.com` now redirects to `joinodf.com` and the multi-track structure (ODE for engineers, etc.) is gone after successive contractions. Budget zero effort here.
- **Pioneer no longer invests.** The site is up and the accelerator page still reads as active; the funding program is not.
- **`foundersinc.com` is a squatted/parked domain** that redirects to an unrelated personal site. Founders, Inc. is `f.inc`. This one is easy to ingest by mistake.
- **`ycombinator.com/jobs/role/software-engineer-intern` returns HTTP 200 and looks like an intern filter — it isn't.** It serves the generic software-engineer list (page title confirms). Real intern filtering requires the logged-in `workatastartup.com/companies` search with `jobType=intern`.
- **The commercial Getro API is not the free one.** `getro.com/api` (403, sales page) and `api.getro.com/v2/networks/<id>/jobs` (401, customer token) are both dead ends. The unauthenticated path is `api.getro.com/**api**/v2/collections/<id>/search/jobs`. One path segment separates a working pipeline from a sales call.
- **HTTP 406 from Getro is rate limiting, not a bad request.** Easy to waste hours "fixing" a body that was already correct. Same for workatastartup.com.
- **YC's Algolia public key rotates.** A key published in a 2025 write-up returned `403 Invalid Application-ID or API key` on test. Extract it from the live bundle or use `yc-oss.github.io/api` instead.
- **Delaware incorporation search is a tarpit.** ASP.NET viewstate, captcha, name-search only, no bulk export, and a new DE entity has no correlation with hiring for months. It sounds like the ultimate upstream signal; it is not worth the build.
- **Wellfound is the highest-value and highest-cost row here.** Cloudflare + DataDome means an HTTP-only scraper will never work. Either commit to a stealth browser or accept that Wellfound is a manual-check source — do not half-build it.
- **PitchBook/Crunchbase-paid are not worth funding for one student.** Check whether the university library already provides PitchBook; if so it is manual-only, and the free TechCrunch + Crunchbase-News RSS + SEC Form D combination captures most of the same signal for zero dollars.
